## a.2 TCP（工具坐标系）标定：四点法

### 原理

工具尖端相对法兰有一个未知偏移 **t**（在法兰坐标系中）。让尖端用 4 种不同姿态接触**同一个空间点 P**，就得到 4 个方程：

```
p_i + R_i · t = P        i = 1..4
   p_i = 第 i 次的法兰位置（世界系，可测）
   R_i = 第 i 次的法兰姿态（世界系，可测）
   未知量 = t（3 个）+ P（3 个）
```

12 个方程、6 个未知量 → 最小二乘可解。消掉 P 更简单：用第 1 个方程减其余 3 个，

```
(R_i − R_1) · t = −(p_i − p_1)          i = 2,3,4      → 9 个方程解 3 个未知量
```

这就是"三点法/四点法"的代数本质：**标定 = 解线性方程组**，不是玄学。

### 仿真怎么做（重要：数据是"合成测量"）

真实标定靠人拿工具去碰台上的一个针尖；仿真里没法真的碰，所以我们用**等价做法**：

1. 在 `tcp` 节点下挂一个虚拟探针（`CylinderGeometry`，长 0.15 m，沿 tcp 局部 +Z），
   定义真值 `t_true = (0, 0, 0.15)` m；
2. 选一个参考点 `P = (0.15, 0.35, 0.30)` m（工作台面上一点）；
3. 随便选 4 组关节角（**姿态差别越大越好**），用你自己的 FK 算出法兰位姿 `(p_i, R_i)`；
4. 令"测得的法兰位置"为 `p_i = P − R_i · t_true`——这正是"尖端恰好碰在 P 上时法兰应在的位置"；
5. 现在只把 `(p_i, R_i)` 交给标定算法求 `t̂`，比较 `t̂` 与 `t_true`。

> 这一步要写进报告：**合成测量与真机测量的数学结构完全相同**，区别只在数据来源；第 5 步加 σ=0.5 mm 噪声再解一次，看最小二乘的鲁棒性——这就是"标定精度评估"。

### 实现清单

| 步骤 | 代码要点 |
|---|---|
| 挂探针 | `const tool = new THREE.Mesh(new THREE.CylinderGeometry(0.004, 0.004, 0.15)); tool.position.z = 0.075; tcp.add(tool);`（圆柱默认沿 Y，先转 90° 再沿 Z） |
| 取法兰位姿 | `flange.getWorldPosition(p)` / `getWorldQuaternion(q)` → `Matrix4().makeRotationFromQuaternion(q)` |
| 组装 A、b | `A` 为 9×3：逐行 `R_i − R_1`；`b` 为 9：`−(p_i − p_1)` |
| 解 3×3 | 法方程 `(AᵀA) t = Aᵀb`，自己写 10 行高斯消元（浏览器里没有线性代数库） |
| 求 P | `P = p_1 + R_1 · t` |

## a.3 用户坐标系标定：三点法

### 原理

给定用户坐标系的三点（都在基座系里量出）：

- `O`：原点；
- `X`：x 轴方向上一点；
- `Y`：xy 平面内（y 侧）一点。

构造：

```
x̂ = normalize(X − O)
ẑ = normalize((X − O) × (Y − O))      // 右手系，先定 z
ŷ = ẑ × x̂
T_user = [ x̂  ŷ  ẑ  O ]               // 4×4，R 的三列就是 x̂/ŷ/ẑ
```

### 验证（这是要求 a 里"验证坐标变换正确性"的落点）

1. 同一 TCP 位姿在两系中的表示互转：`p_user = T_user⁻¹ · p_base`，再转回来误差 < 1e−6；
2. 姿态同理：`R_user = R_userᵀ · R_base`（`R_user` 是用户系的旋转），换回基座系误差 < 1e−6；
3. 用用户系表达一个目标：`p_target_user = (0.1, 0.1, 0)`，换回基座系 `p_target_base = T_user · p_target_user`，再用你的 FK/IK 检查是否可达（不需要真的解 IK，给出位姿即可）。

### 记录表

| 项 | 数值 |
|---|---|
| O / X / Y 三点（基座系，m） | |
| x̂ / ŷ / ẑ（3×3 旋转矩阵） | |
| T_user（4×4，保留 6 位） | |
| 互转误差（位置 / 姿态） | |

## b.2 关节空间插值：MOVJ 的核心

MOVJ = Move Joint，**只在关节空间从 A 到 B**，路径形状不可控，但不需要 IK。

归一化时间 `u = t/T`，插值函数 `s(u)` 有三档，必须做对比（任务 c 要用）：

| 方案 | s(u) | 端点速度 | 端点加速度 | 现象 |
|---|---|---|---|---|
| 线性 | u | 阶跃 | 无穷大 | 起停"顿"，速度曲线是矩形 |
| smoothstep | 3u²−2u³ | 0 | 阶跃 | 平滑一些，仍有加速度突变 |
| **五次多项式** | 10u³−15u⁴+6u⁵ | 0 | 0 | **速度、加速度都连续**，推荐 |

关节角更新：

```js
const s = 10*u**3 - 15*u**4 + 6*u**5;
const qj = qStart[j] + (qEnd[j] - qStart[j]) * s;
setJoint(joints[j], qj);
```

每段时长建议按"最大关节位移 / 关节速度上限"取（真机 velocity limit 在 URDF 的 `limit.velocity`；本素材没给，统一用 0.6 rad/s 折算），再用速度倍率缩放：

```js
const T = Math.max(...|Δq_j|) / (vmax * speedScale);
```

## b.3 执行状态机

```
idle ──执行──> running ──到段尾──> 下一段 … ──最后一段──> done
                 │  ↑
              急停/暂停 ┘（恢复时必须从"当前关节角"续算，不能跳回段首）
```

要求：

1. 逐帧（`requestAnimationFrame`）推进时间，**不要**写 `setTimeout(1.6s)`；
2. 每帧看 `state.estop`：急停立即冻结，恢复后从冻结处继续；
3. 速度倍率实时生效（把倍率乘进 `dt`）；
4. 执行时同步记录 TCP（下一个任务要用）。

# 阶段 9｜任务 d：可达区域分析（0.75 h）★采分点

## d.1 方法

```
对 k = 1..N：
  θ_j ~ U(limit_j.lower, limit_j.upper)     j = 1..5        （蒙特卡洛均匀采样）
  setJoint(...)                              （或直接矩阵连乘，见下）

点云 {p_k} → 统计 + 投影 + 密度
```

`N ≥ 1e5`。性能提示：

- 必须先把当前位姿存下来、算完再恢复（否则"采样完机器人跑到奇怪位置"是常见 bug）；
- 分帧执行（每帧 5000 个），否则页面会卡死 1–2 秒；
- 如果嫌 `updateMatrixWorld` 慢，可以用阶段 5 第 3 档的矩阵链直接算位置（只算位置快一个数量级），但报告里要写明用的是哪种。

## d.3 要求的分析（3 条以上）

1. **工作空间形状**：why 这么扁？——因为 J1/J2/J4 三根轴都平行于世界 X（俯仰），只有 J3（前倾 28°）和 J5 能改变 x；所以工作空间是"沿 YZ 展开的厚片"，x 方向只 0.49 m。

3. **工位布置**：结合边界与空洞，给出"工件应放在 (…, …, …) 附近、避开 (…)"的具体建议；并指出"可达 ≠ 可用"——y<0 的点云虽然在数学上可达，但会穿过地面/基座。
