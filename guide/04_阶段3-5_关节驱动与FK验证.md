## 0. 三个阶段在做什么

```
阶段3 建表            阶段4 驱动                    阶段5 读位姿 + 验证
名字→节点, qZero   →  q = qZero · Ry(θ), clamp  →  matrixWorld → TCP 读数 → 三档对拍
   ↓ 关口3              ↓ 关口4                       ↓ 关口5
5 个关节、限位正确     5 个滑块能动、不超限、急停有效   零位/单关节/随机的数值都能对上
```

整个实验一的技术核心就三行代码：

```js
const qZero = node.quaternion.clone();                     // ① 记住静止姿态（R_fix）
node.quaternion.copy(qZero).multiply(qRy(θ));              // ② 在它上面右乘关节角
tcp.getWorldPosition(p); tcp.getWorldQuaternion(q);        // ③ 让场景树替你算 FK
```

## 1. 阶段 3｜建关节表（0.75 h）

### 1.1 目标数据结构

`robot.js → buildJointTable(robot, jointMap)` 返回 5 个对象：

```js
{ name: 'J1', node: Object3D, axis: Vector3(0,1,0),
  lower: -Math.PI, upper: Math.PI,     // 弧度
  angle: 0,                            // 当前角（弧度）
  qZero: Quaternion }                  // 零位静止旋转 R_fix
```

### 1.2 六步实现

1. **按名字找节点**：`robot.getObjectByName('J1')` … `'J5'`。
   ⚠ 讲义 P18 的 `node.userData.joint === true` 在本素材上会**静默返回 0 个关节**——GLB 里 14 个节点的 `extras` 全空。这是"元数据幻觉"坑，很多人会卡一晚上。
2. **取 qZero**：`node.quaternion.clone()`。它是常量，之后每次驱动都在它上面叠加，绝不能改。
3. **轴**：`new THREE.Vector3(0, 1, 0)`（局部 +Y）。
   ⚠ 不是 +Z！joint_map 的 convention 写"绕局部 +Z"是 **Blender 语言**；Y-up 重标定后，Blender 的局部 +Z 在 glTF/Three.js 里就是局部 +Y。用 +Z 的后果：五个关节整体差 90°，J5 会让 TCP 跑偏。
4. **限位**：`jointMap.joints.find(j => j.name === name).limit`，单位是**度**，转成弧度存（`THREE.MathUtils.degToRad`）。期望：J1 ±180、J2 ~ J4 ±120、J5 ±180。
5. **对拍**：建完检查 `joints.length === 5` 且顺序 `J1..J5`；数量/名字不对直接 `throw`（这就是讲义 P18 的 `validateAgainstMap`，把"带病运行"挡在加载期）。
6. **角度初值 0**，并把 qZero 应用到节点上（保证零位一致）。

### 1.3 检查点：把表打出来

```js
console.table(__LAB__.joints.map(j => ({
  name: j.name, lower: (j.lower*180/Math.PI).toFixed(0), upper: (j.upper*180/Math.PI).toFixed(0),
  qZero: [j.qZero.x, j.qZero.y, j.qZero.z, j.qZero.w].map(v => v.toFixed(4)).join(',')
})));
```

期望的 `qZero`（顺序 x, y, z, w，可直接对拍）：

| 关节 | qZero (x, y, z, w) | 含义 |
|---|---|---|
| J1 | (0.0000, 0.0000, 0.7071, 0.7071) | 绕 Z +90° |
| J2 | (−0.7071, 0.0000, 0.7071, 0.0000) | 复合，含 Z +90° |
| J3 | (−0.3320, 0.0000, −0.6243, 0.7071) | 复合 |

> 四元数 (x,y,z,w) 与 (−x,−y,−z,−w) 表示同一旋转，符号不同不算错。

### 1.4 常见错误

| 症状 | 根因 | 排查 |
|---|---|---|
| `joints.length === 0` | 用了 `userData.joint` | 改按名字找 |
| 某个关节 `undefined` | 大小写/空格（`J1` vs `j1`） | 先 `traverse` 打印全部 name |
| 限位是 180/120 但单位混乱 | joint_map 用度，代码用弧度 | 统一弧度，界面显示时再转 |
| 一加载模型就变形 | 建表时误改了 `node.quaternion` | 只 clone，不改 |

## 2. 阶段 4｜驱动一个关节 + 示教器（1 h）

### 2.1 setJoint：两行数学 + 一行钳制

```js
function setJoint(joint, angleRad) {
  const q = Math.max(joint.lower, Math.min(joint.upper, angleRad));   // ① 先钳制
  const qy = new THREE.Quaternion().setFromAxisAngle(joint.axis, q);  // ② Rodrigues（轴角→四元数）
  joint.node.quaternion.copy(joint.qZero).multiply(qy);              // ③ 右乘叠加
  joint.angle = q;                                                    // ④ 留痕给界面/轨迹
}
```

三点必须理解：

- **先钳制后驱动**：真机上超限就是撞限位块/报警；仿真里先 clamp，滑块拖到边界也不会飞出。
- **右乘**：`q = qZero · qy` 才是"绕关节自身轴转"；写成 `qy · qZero` 变成绕世界轴转，臂会整体歪。
- **不要覆盖 qZero**：这就是为什么 `setRotationFromAxisAngle` 不能用（讲义 P19 那段代码在本素材上不适用）。

### 2.2 示教器面板（对应 `ui.js` 的 STEP 6）

讲义 P20 的功能清单，落到本模型是 **5 个关节**（不是 6 个）：

| 功能 | 要求 | 本工程落点 |
|---|---|---|
| 关节滑块 + 数值 | 5 个，范围 = 限位，步长 0.1°，显示度数 | `ui.js` TODO |
| 关节角显示 | 每个关节当前角度（度） | 滑块自带数值即可 |
| 世界坐标显示 | x/y/z + RPY | `index.html` 右侧 TCP 卡片（阶段 5 填数） |
| 使能/失能 | 失能后滑块禁用 | 已实现 |
| 急停 | 一键冻结，优先级最高 | 按钮已实现；`onChange` 里要 `if (state.estop) return` |
| 速度倍率 | 10%–100% | 已实现（阶段 7 执行程序时才真正用它） |

滑块写法要点：

```js
const proxy = { value: THREE.MathUtils.radToDeg(joint.angle) };
const ctrl = folder
  .add(proxy, 'value', THREE.MathUtils.radToDeg(joint.lower), THREE.MathUtils.radToDeg(joint.upper), 0.1)
  .name(joint.name + ' (°)')
  .onChange((deg) => {
    if (state.estop) { proxy.value = THREE.MathUtils.radToDeg(joint.angle); return; }  // 急停拒绝新指令
    setJoint(joint, THREE.MathUtils.degToRad(deg));
  });
```

## 3. 阶段 5｜位姿读取与 FK 三档验证（0.75 h）

### 3.1 readTCPPose：读场景树，不要自己乘

```js
function readTCPPose(tcp) {
  const p = new THREE.Vector3();      tcp.getWorldPosition(p);
  const q = new THREE.Quaternion();   tcp.getWorldQuaternion(q);
  const e = new THREE.Euler().setFromQuaternion(q, 'XYZ');   // RPY（弧度）
  return { position: { x: p.x, y: p.y, z: p.z },
           quaternion: { x: q.x, y: q.y, z: q.z, w: q.w },
           rpy: { r: e.x, p: e.y, y: e.z } };
}
```

显示层：位置 4 位小数、RPY 用度并保留 2 位、四元数 3 位（`index.html` 里已留好位置）。
为什么要同时显示 RPY 与四元数：RPY 给人读，四元数与外部程序对数；两者换算只在显示层做（`Euler.setFromQuaternion` / `Quaternion.setFromEuler`）。

#### 第 3 档 · 随机位形对拍（自写 FK vs 场景树）

思路：自己写一个"矩阵连乘"的 FK，与引擎算出的 `tcp.matrixWorld` 比较，100 组随机关节角，最大误差应 < 1e-6 m。

```
T(world, tcp) = T_root · L_J1 · Ry(θ1) · L_link1 · L_J2 · Ry(θ2) · … · L_tcp
```

- `L_i` = 零位时该节点相对父节点的局部矩阵（`node.matrix` 在零位时就是它）；
- 关节那个 `Ry(θ)` 直接乘在关节节点矩阵后面（右乘）；
- 顺序必须与场景树一致：**J 与 link 交替**。

实现建议：在 `buildJointTable` 里顺手把零位局部矩阵 `node.matrix.clone()` 存一份（`joint.L` 与 `link.L`），FK 里用 `Matrix4.multiply` 连乘。

> 关于"DH 手算"：讲义 P08 希望你能对 DH 表手算零位。本素材的 `joint_map.dh.matrix` 其实是**零位局部变换矩阵**（行主序，旧备份是列主序），不是经典 DH 参数表；所以本实验的"手算"改成了上面这条矩阵链——数学等价，而且能直接和场景树对拍。想练经典 DH，用 `Modern Robotics` 的 UR5 参数在纸上做，不要用本素材的数据。

## 附录｜自测参考答案要点

- **2.4-1**：`qZero` 是每个关节各不相同的常量，必须保存副本；`axis` 对五个关节都是同一个常量 (0,1,0)，可以直接复用。
- **2.4-2**：先驱动后钳制 = 界面显示的角度可能超过限位、矩阵已经被写到超限位置，再钳制会出现"跳回"；而且超限一刻的中间状态会被轨迹记录采到。
- **2.4-3**：左乘 = 绕父/世界轴转；J1 会变成"整体绕世界 Y 轴旋转"（把机械臂当陀螺转），而不是肩部俯仰。
- **3.4-1**：`L_i` 只含常量部分（平移 + R_fix），变量部分由 `Ry(θ)` 单独乘；若取驱动后的矩阵，等于把变量乘了两遍。
- **3.4-2**：`getWorldPosition` 会先 `updateWorldMatrix(true, false)` 沿父链刷新祖先矩阵，再读 `matrixWorld` 的第 4 列；所以每帧读之前不一定要手动 `updateMatrixWorld`（但批量改完关节后建议显式刷一次）。
- **3.4-3**：J5 列。+Z 轴时 J5 的世界轴变成水平方向，TCP 相对轴心有 5.7 mm 的力臂，转 90° 会让读数位移接近 8 mm，肉眼在 4 位小数下一眼可见。
